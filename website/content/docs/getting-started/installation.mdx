## macOS

1. On the [download page](/download), choose **Apple silicon** for M-series Macs or **Intel** for older Macs.
2. Open the `.dmg` and drag Termy to `/Applications`.
3. Open Termy from Applications.

macOS DMGs from v0.2.75 onward are signed and notarized. If Termy does not open,
[see the troubleshooting guide](/docs/getting-started/troubleshooting).

## Linux

Download the AppImage or `.tar.gz` from [GitHub Releases](https://github.com/lassejlv/termy/releases).

- **AppImage:** mark it executable, then run it.
- **Archive:** unpack it and run the included Termy binary.

Linux release launchers prefer X11/XWayland when it is available so the desktop
window manager can provide the native title bar and window controls. To run the
Wayland backend instead, launch Termy with `TERMY_LINUX_BACKEND=wayland`.
Both terminal and Settings windows request system-managed decorations, including
KDE's title bar, window controls, and resize borders. The window manager controls
the titlebar theme independently of Termy's terminal color theme.

## Windows

1. From [GitHub Releases](https://github.com/lassejlv/termy/releases), download the installer for your PC:
   - `Termy-<version>-windows-x64-Setup.exe` for Intel and AMD PCs.
   - `Termy-<version>-windows-arm64-Setup.exe` for ARM64 PCs such as Snapdragon laptops.
2. Run the installer. By default it installs Termy for your account only, in
   `%LOCALAPPDATA%\Programs\Termy`, without an administrator prompt. To install
   for every user under Program Files, choose **Install for all users** when
   Setup asks, or run it with `/ALLUSERS`.
3. Open Termy from the Start menu. A desktop shortcut is optional; tick it on
   the **Additional tasks** page.

Termy checks for updates itself and installs them in the same place, for the
same users, as the existing install.

The Windows installer is not code-signed, so Windows SmartScreen may show
**Windows protected your PC** with an unknown publisher. Choose **More info**,
check that the file name is the one you downloaded from the Termy release, then
choose **Run anyway**. To confirm the download, compare its SHA-256 hash
(`Get-FileHash .\Termy-<version>-windows-x64-Setup.exe` in PowerShell) with
`checksums.txt` on the same release.

## Video on Windows

Playing a video uses libVLC 3 from a `vlc` folder next to `termy.exe`. Termy
does not install VLC, and that folder is not downloaded by the installer on its
own. The tested files are the official VideoLAN **3.0.24** 64-bit archive
(not a statement that 3.0.24 is the newest release):

https://download.videolan.org/pub/videolan/vlc/3.0.24/win64/vlc-3.0.24-win64.zip

`sha256 fcf30850371ad10c9373cc4f0f4501e7dee49e3e9ae9f20c72fb2661a1ca6323`

Before building the Setup exe, stage that archive with
`scripts/windows/stage-libvlc.ps1`. The script copies `libvlc.dll`,
`libvlccore.dll`, and the playback plugins. It leaves `vlc.exe` out and does
not modify `C:\Program Files\VideoLAN\VLC` if VLC is already installed. Photos
stay inside Termy without this folder. A missing or incomplete `vlc` folder
makes video fail with an error. Termy does not open VLC's own window or mpv
instead. The DLLs must be 64-bit; a 32-bit tree is rejected.

The archive's `COPYING.txt` is GPL-2.0. libVLC is LGPL-2.1-or-later, and the
plugins are not uniformly LGPL. The matching source archive is
https://download.videolan.org/pub/videolan/vlc/3.0.24/vlc-3.0.24.tar.xz.
A public Termy release that includes these binaries still has to ship or offer
that source. That release step is not done here.

Termy will also be available through winget as `lassejlv.Termy` once the
package is accepted into the winget repository:

```powershell
winget install lassejlv.Termy
```

## From source

```bash
git clone https://github.com/lassejlv/termy
cd termy
cargo run --release -p termy
```

This route requires Rust and the platform dependencies used by the desktop app. Prefer a release binary unless you are developing Termy itself.
